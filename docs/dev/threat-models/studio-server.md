# Studio Server: threat model (4.2.1 to 4.2.3)

**What it does.** A Studio shared by a team on one server (plan `docs/dev/PLAN-4.2.1-4.2.3-STUDIO-SERVER.md`, ADR
0025 and 0027):
- people authenticate with an OpenID Connect provider (Keycloak or any other), and the rights live in the Studio
  (owner, dev, reviewer);
- the game's files are written through a journal that is durable and fenced;
- hosted, the truth is PostgreSQL and an S3 store (Cellar), and the instance's folder is a cache.

4.2.1 serves the API, the authentication and the members, the processing worker (§3.8), the game's origin with its
tickets and its previews (§6.1; 4.2.2: one build per revision, plan 4.2.2 §2.2), and the Studio's page.

**Assets:**
- the game's sources and assets, which are private to the project;
- the sessions;
- the refresh tokens and id_tokens, encrypted;
- the server's secrets: the OIDC client secret, the session key, the database and S3 credentials;
- the members and the audit log;
- the journal's integrity.

**Adversaries:**
- anyone on the Internet;
- a member with less than the role they act as;
- a hostile page in a member's browser (CSRF);
- a stolen or replayed token;
- a member who leaves while still holding tokens;
- an unreachable or misbehaving provider;
- a second instance of the server during a redeploy.

| Two identities on one request | An `Authorization` header selects policy B and the cookie is ignored: a bad token is a 401 whatever the cookie | test |
| A forged or misused token | Signature by the provider's JWKS (RS256, PS256, ES256, EdDSA; never `none` or HMAC), issuer, **our audience** (distinct from the browser client), `exp − iat` ≤ 5 min, `iat` after the user's `revoked_before`; an id_token as a Bearer is refused | test (`alg: none`, id_token, other audience, 1 h lifetime, non-member) |
| Login flow attacks (code injection, replay, open redirect) | Code + PKCE S256 + state + nonce, checked by `openid-client`; the pre-authentication is used once (10 min); the return path is a plain relative path (letters, digits and `/._~%?&=#+,:@-` only, so no tab or backslash a browser would rewrite) | test (callback replayed, `//evil`, `https://…`, `/\t/evil`) |
| Invitation abuse | One use, 7 days, stored hashed (also while a login carries it); consumed only by the provider-verified email it names; never demotes the last owner | test (other email, unverified, reused, last owner) |
| A member removed keeps working | Sessions deleted and `revoked_before` set at once; a removal, a demotion or an ended session is emitted on the revocation bus, and the live streams (`/api/events`) of that user or session close at once; a stream also closes when its Bearer token ends, and its credential is checked again every 30 s (a demotion below reviewer closes it) | `tests/studio-auth.test.ts` (session 401, Bearer 401 after removal), `tests/studio-collab.test.ts` (a removed member's stream closes within 5 s; a Bearer stream closes at its token's end) |
| A live stream wearing the server down | One read of the leases per change for all the streams (coalesced, in order); a stream more than 1 MiB behind is closed (its client reconnects and reads `/api/ops`); a stream's check of its credential never keeps the session alive | review |
| A member overwriting another's work | Every file belongs to one span; a write claims the spans of its files, all or none, in the transaction of its intent; a span another member holds is a 423 naming them; leases last 120 s, renewed by the heartbeat; a client sending its fences is refused once its lease was taken over; the exclusive lease waits for no span held by another and blocks every claim; a removed or demoted member's leases are released at once | `tests/studio-collab.test.ts` (and the race on Postgres) |
| A hostile game in a member's browser | Everything that runs the game is served on `playUrl`, another origin, chosen by `Host`; it serves no Studio API and the Studio's `__Host-` cookie never goes there. Access is a game session made from a ticket (once, 60 s, a member's browser session, a relative path) and kept in a partitioned cookie (`SameSite=None; Partitioned`), 15 min sliding, never past its Studio session nor R = 15 min after the provider last confirmed that session; every request checks the game session, its Studio session and the membership again. Answers carry `frame-ancestors` the Studio and `no-referrer` | `tests/studio-play.test.ts` |
| The Studio's page running foreign code | The page and its scripts come from the Studio's origin only (`script-src 'self'`); it frames the game's origin only (`frame-src`), is framed by nobody else (`frame-ancestors 'self'`) and calls its own origin only (`connect-src 'self'`). It holds no data: the game's images and sounds on that origin are served to members only | `tests/studio-client.test.ts` |
| The game's origin serving more than the game (4.2.2) | No Vite and no source on the server: the game's origin serves, behind the game session, GET only, the files of a revision's build (built where the game's code runs: the worker, from the revision's snapshot, which never holds `private/`, `tests/` or `playtests/`) by the hashes the Studio stored, the prepared assets (the Studio's prepared set, then `publicDir`) by an allow-list of folders, resolved inside them, and the published builds under `/play/<n>/`. Paths with `..`, `.`, a backslash or a NUL are refused before any lookup; a revision unknown in this epoch is a 404. The worker's result is bounded (2,000 files, plain relative paths, base64) and checked by the Studio, which picks the keys (content hashes). The page is revalidated at each load (an ended session is refused then); only its code, named by hash, is kept by the browser | `tests/studio-client.test.ts` (no `package.json`, no source, no private note, no unknown revision, no Studio API, no write), `tests/studio-previews.test.ts`, `tests/studio-worker.test.ts`, `scripts/e2e-studio-hosted.ts` |
| A published build open to anyone (4.2.2) | `/play/` needs the game session unless an owner sets `publicBuilds` (off by default); even then only `/play/` and `/play/<n>/` are open (`PUBLIC_BUILD_PATH`), never a preview or the Studio's API | `tests/studio-builds.test.ts` |
| A forged build manifest (4.2.2) | The manifest (epoch, revision, engine, snapshot and file hashes) is canonical and signed with the Studio's job key under its own prefix (`web-scumm build manifest v1\n`), so a job's signature can never pass for a manifest's; an owner's fresh rebuild compares it byte for byte | `tests/studio-builds.test.ts` |
| Undo used against another's work (4.2.2) | Undo and redo take only the member's own operations; a file another wrote since is a 409, a span another holds a 423; the stacks are per member, in the database | `tests/studio-undo.test.ts` |
| A bisection or the health wearing the worker down (4.2.2) | One health job at a time (a serial gate), ⌈log₂ n⌉ checks per bisection, never past the head; a dev asks for one; a revision that cannot be judged after 5 failures says so | `tests/studio-health.test.ts` |
| The asset tools' packages (4.2.2) | Installed on the worker only, from `requirements.txt` (hashed, D54): wheels only, every hash checked (`--require-hashes`); `prepare` runs there with an emptied environment, under the project's exclusive lease, its output bounded (30 MiB, 2 min) | `tests/python-requirements.test.ts`, `tests/studio-prepared.test.ts` |
| An uploaded file as an attack (4.2.3) | An upload is untrusted bytes: bounded before it is read (its body by its length, then 10 MiB once decoded: 413) and typed by its magic number (a PNG, JPEG or WebP image, named by that type; an Ogg, MP3 or WAV sound whose extension and bytes agree: 415 otherwise). The magic bytes only sort out the plainly wrong file: a polyglot (a valid PNG that is also HTML or script) passes them. What defends is how it is served: as the image or sound type its name says, with `nosniff` and a `default-src 'none'; sandbox` CSP, so a browser never renders it as a page nor runs it; it is written as one operation of the journal, never run nor parsed as a picture or a sound by the server. A sheet is cut by Python on the worker only (no game code, an emptied environment, its child killed with its group on a cancel or at 2 min), from a snapshot of that image, that sheet's cells and `site.json`; its answer is refused unless every file is a cell of the sheet asked (`art/<sheet>/r<row>c<col>.png`, or the one cell keyed), 99 × 99 at most. A file of `art/` or `audio/` is served back to members only, its links followed and still under those folders (a link out of them is a 404), opened before its headers (a file gone meanwhile is a 404, never a crash). On a hosted Studio the listing reads no source outside the game folder (`sources.json` paths elsewhere are ignored), and a picture's size is read from its first 64 KiB | `tests/studio-assets-hosted.test.ts` |
| A long job holding the project (4.2.3) | One job at a time, four waiting at most (429); a cancel (its author or an owner) closes the worker's request, which kills the child, and leaves no operation and no lease held; a job writing is past cancelling (409), so a cancel never leaves half a write | `tests/studio-assets-hosted.test.ts` |
| The engine's upgrade breaking or seizing the game (4.2.3) | `POST /api/engine/migrate` is an owner's, hosted only (404 otherwise); it runs under the owner's exclusive lease (the others' writes wait, refused with the owner's name), one at a time (429). The migration runs on the worker (a `migrate` job: the game's code is loaded there only); the game's code shapes the answer; the Studio bounds it to the migration's files (`rooms/*.ts`, `rules.ts`, `items.ts`, `game.ts`, `locales/*.json`, each one the snapshot has, and the two id maps; 1,000 files, 8 MiB). The lease is renewed while it runs and given back by the owner's last exclusive operation only. The migrated game is judged on the worker (the validator, then the solver from a new game, bounded) before anything is written: a failure or a verdict the solver cannot give is a 422 and the head is untouched; otherwise one operation, through the guard, each file compared with the content it was computed from (409), undoable by the owner. What it does not cover: a game that passes both and still behaves differently to a player (a save of the old schema follows the ids' migration step it writes) | `tests/studio-engine-upgrade.test.ts` |
| A crafted backup (4.2.2) | A backup is trusted input, as the database's credentials are: it can add owners. Its digest says it is whole, not who made it; a restore still checks its tables against the registry and its columns against the schema, goes into an empty database only, and replays only operations that continue the head | `tests/studio-backup.test.ts` |
| A hostile game writing in a member's name | On the game's origin the room editor never writes. A save starts only from the member: the Studio's "Save layout", or their yes before a change that would reload the view (the view's own messages never start one). The Studio takes a layout from the view only as the answer to that request (a nonce), for the room it shows, from the exact game origin, then writes it itself as the member, under their lease. The game's page cannot read the Studio's page, nor call its API with the member's session (no cookie crosses, CORS refuses) | `scripts/e2e-studio-hosted.ts` (Chromium and WebKit: a layout sent unasked is ignored; the parent, the API and a write are out of reach) |
| The metrics read by a stranger, or used to guess the token (4.2.3) | `GET /metrics` exists only when the secret `STUDIO_METRICS_TOKEN` is set (32 characters at least; 404 otherwise), answers to `Authorization: Bearer <token>` only, compared in constant time (both sides' sha256, then `timingSafeEqual`), never to a session, never on the game's origin; with OIDC, refused tokens are counted for the address (past 30 a minute they get 429; a right token is never slowed: the token's 32 random characters are the protection). What they reveal: counts and durations of operations, jobs by kind, 423s and answers by status class, the head revision, the RPO, whether the instance holds the service lease: how busy the team is and when, never a path, a name, an author or a file's content. The daily backup it sits beside goes to the instance's own bucket (`backups/`), as trusted as the blobs: it survives the database, not the bucket or its credentials | `tests/studio-metrics.test.ts` (404 without the secret, 401 with none or another, the comparison through `timingSafeEqual`, 404 on the game's origin (on a hosted Studio a request without the game's session gets that origin's 401 first: the reference run), no path or author in the text; `--keep` deletes only the backups it wrote) |
| An owner's takeover abused | Owners only; audited with the previous holder | `tests/studio-collab.test.ts` |
| A user disabled at the provider | The session is re-checked every 5 min with its refresh token. A definitive refusal ends it; a provider unreachable past R = 15 min suspends it (503, fail closed). One refresh per session at a time, and a slow one still stores the rotated token, so a provider that revokes used refresh tokens never logs anyone out by mistake. A refresh token that no longer opens ends the session. `invalid_client` (our own configuration) is not a refusal of the user | test (simulated clock: disabled, down 16 min, back; 5 concurrent requests, one refresh; a 6 s refresh; an unreadable token); `tests/studio-keycloak.test.ts` (a user disabled in a real Keycloak: the next refresh is refused for good) |
| A forged back-channel logout | Form-encoded `logout_token` checked per OIDC Back-Channel Logout 1.0 (signature, `typ`, issuer, audience = client, `events` with an object for the event, no `nonce`, `iat` ≤ 5 min, `jti` never seen). With a `sid`, only that provider session ends; a `sub` alone ends every session and token of the user | test (replay, nonce, no event, JSON body, `sid` + `sub` leaves the other devices); `tests/studio-keycloak.test.ts` (a logout token a real Keycloak sends, verified) |
| The last owner locked out | The last owner can be neither demoted nor removed (409) | test |
| Secrets leaking | Secrets from 0600 files or Clever's variables, removed from `process.env` at start (children never inherit them), never logged; refresh tokens and id_tokens sealed with AES-256-GCM (key ring of secrets of 32 characters or more; the key and its id derived apart by HKDF); session and invitation tokens stored as sha256; the CLI's token file written whole at 0600 and renamed, under a lock, and sent to https servers only | `tests/studio-server.test.ts` (secrets), `tests/studio-auth.test.ts` (session key, CLI over http) |
| Brute force on `/auth/*` | 30 requests per minute per address on `/auth/*`; past 30 refused credentials per minute, that address's refusals become 429. A request with a valid credential is never slowed, so a stranger cannot lock the team out; with OIDC beyond the loopback, `trustProxy` is required, so clients are told apart behind Clever's proxy | `tests/studio-server.test.ts` (trustProxy required), review |
| Another member's stored answer | A write's stored answer (`x-studio-op`) is kept per author: knowing another member's operation id gives nothing | test |
| A stale instance writing (redeploy) | A fenced service lease plus the journal's fenced per-operation lease; the instance stops writing by its own clock before the lease can expire; Postgres cuts a frozen transaction within 5 s | `tests/studio-journal.test.ts`, `tests/studio-server.test.ts` |
| Content code reading secrets | With OIDC, the game's code (validation and the loads behind the Studio's reads) runs only in `studio-worker`, a separate application with no secret of the platform, in a fresh child with an emptied environment and no pipe, killed with its process group at its deadline; a survivor in the group recycles the instance (a process that leaves the group is not detected: periodic redeploys, ADR 0028). A failure fails the guard closed and is never cached. `loadConfig` refuses OIDC without a worker; captures are unavailable hosted | `tests/studio-worker.test.ts` (emptied environment, deadline, an escaped process does not hang the worker, logs do not corrupt output, no false survivor, failures not cached, the Studio reads through the executor), `tests/studio-server.test.ts` (worker required) |
| A forged or replayed job | Jobs signed with Ed25519 by the Studio, the worker holding the public key only; the signature binds id, instance, epoch, revision, snapshot hash, kind, parameters, staging prefix, expiry (≤ 5 min, plus 30 s of clock skew allowed on the worker) and the two presigned URLs; a job is run once per worker process, never after its expiry (checked again when it leaves the queue); another instance's job is refused | `tests/studio-worker.test.ts` |
| A worker naming what the Studio publishes | The Studio reads the result itself (stopping past 32 MiB), checks it answers its job, and deletes the staging prefix; a presigned write reaches its one key only | `tests/studio-worker.test.ts` (another job's answer refused; Cellar scope) |
| A snapshot leaving its folder | Unpacked paths are relative, without `..`, empty segments or dotfiles, text files only, bounded in count and size | `tests/studio-worker.test.ts` |
| The game's repository harmed through the Studio (4.2.3, H5) | Owners only push and import; a push is a new commit on the tip the Studio last pushed or imported, never forced (a moved branch is a 409); the deploy key writes one repository (D44), is a secret, and lives in a 0600 file for the duration of one git command, with an environment of its own (no platform secret, no prompt, no user configuration); a remote URL with credentials is refused at start; no working tree is ever checked out (objects only), so the repository's links, attributes and ignore rules never reach the server's files, a link or submodule in the game, or the game's folder itself as one, refuses the import; the game's `private/` never goes to the repository and an import never deletes it; an email is co-author only when verified; an import is one revision under the exclusive lease, through the guard; residual: without `git.knownHosts` the remote host is trusted on first use, again after each new disk | `tests/studio-git.test.ts` |
| An AI agent through the remote MCP (4.2.3, ADR 0029) | `/mcp` takes an access token for this Studio's audience only (policy B), never the session cookie; it is stateless, so no stream outlives a revocation; each tool is a request to this server's own `/api` on the loopback with the caller's token: the gate, the role, the spans, the journal and the replay are the API's own code; what needs the repository (screenshots, tests, documents) is not offered | `tests/studio-mcp-remote.test.ts` |

**Residual risks.**
- **The worker runs hostile code with the job's capabilities in reach** (ADR 0028): the presigned URLs and the job
  token are assumed visible to the job's code and, by persistence, to later jobs of the same worker instance until it
  is recycled. They reach that job's snapshot and result for 5 min at most, nothing else. Verdicts and loads from a
  worker are signals in the project's trust domain, never security decisions.
- **A provider without refresh tokens** gives no way to learn of a revocation before expiry, so such a session lives
  15 min at most.
- **Rate limits are kept in memory**, per instance, and do not survive a restart.
- **Any account at the provider leaves a row.** A login by someone who is not a member creates a user and a session
  that reach nothing (403). With a public provider this grows with logins; `/auth/*` is rate-limited per address.
- **Sealed values are not bound to their row.** Someone able to write the database could move a sealed refresh token
  to another session; they could then do far more anyway.
- **Not yet in 4.2.1 PR 5:** the startup check that refuses a route without a policy, and multipart uploads under
  policy A, come with the client routes (PR 7).
- **A lease names a span, not a member's intent:** a member holding a room may write anything in it. Spans are the
  unit of coordination between trusted members, not of authorisation.
- **The game session's cookie is partitioned (CHIPS)** because `*.cleverapps.io` makes the two origins different
  sites. Spike S found it accepted by Chromium, Firefox and WebKit with default settings, and the hosted e2e by
  Chromium, Firefox (CI) and WebKit on macOS. WebKit on Linux stores no cookie a frame of another host sets, even on
  one site, so it is not in CI and cannot stand for Safari; a real Safari, on macOS and iOS, is checked by the
  `studio-hosted` pass. A browser that refuses the cookie fails closed: the game's frame stays empty.
- **A ticket travels in a URL** (`/_ticket?t=`): a proxy in front of the server may log it. It is used once within 60 s,
  so a logged ticket is spent; the server's own log records the path without the query.
- **Login CSRF on the game's origin:** someone who gets a member to open their own ticket puts that member's game frame
  in their game session. It stays within the same project and reads only its previews.
- **A hostile game can alter the layout being saved**, in the room its member is editing: the editor runs in its
  page. The write is still the member's own, in that room only, through the guard.
- **A preview's code stays in a member's browser cache** after their session ends (it is named by hash and kept for
  good): they cannot load its page again, but what they already downloaded is theirs, as any page they saw.
- **The previews take room** (about 1 MB per revision for the sample game, plus files shared by content): their rows
  are kept, so the collection (`gc`, 4.2.2) removes only what no row names any more; pruning old previews is for later.
- **The remote MCP (4.2.3)**: its tokens must carry the Studio's `oidc.audience`, whatever MCP's `resource` asked; the
  loopback's refused tokens are counted for the loopback's address (many at once make the next refusals 429 for a
  minute, never a valid request); the MCP SDK (`^1.32`, with express and hono) now runs in the server process, unlocked
  like the engine's other dependencies.
- **Presence lives in memory** and is lost on a restart (members reappear at their next heartbeat).
- **`fsync` on macOS is not `F_FULLFSYNC`.** This only matters in local mode.
