- **D36 · 2026-10-12** · **Restore has two explicit modes**: `merge` (4.1.19's behaviour: the file's conflicts replaced with `--force`, everything foreign kept) and `replace-store` (the store made identical to the snapshot). **`--mode` is always required** and **both modes require maintenance** (no live writer's lease, `serve` or any command that opens the store for writing, migrations included; migration 0005, one lease per row, database time, a live lease refused rather than waited for, Postgres's advisory lock tried within a bounded time, advisory lock then lease everywhere); 4.1.19 instances must be stopped before the first 4.1.20 restore. `replace-store` accepts only a schema 4 backup whose `completeness` is `whole-store` (tenants, runs, daily and `run_quota`, every SQL table classified by a registry), of the destination's SQL schema, after writing and checking a safety backup (`--safety-out`). Schemas 1–3 stay readable, for `merge` only. The digest is an integrity check, **not a signature**. Supersedes the plan's "the default mode is `merge`". ADR 0023.
