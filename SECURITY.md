# Security policy

Please report vulnerabilities through GitHub’s private Security Advisory feature rather than a public issue. Include the affected commit, reproduction steps and impact; do not include provider keys or private game assets.

The development Studio listens on loopback by default. `npm run studio:lan` and `npm run dev:lan` are explicit LAN modes: they generate a one-session capability token, require same-origin writes and print the authorized URL. Do not forward these development ports to the Internet.

Game TypeScript modules and custom commands are trusted code. quest'n'click does not sandbox an untrusted `games/<id>` directory. Assistant provider keys live in session storage, and custom relay destinations require the explicit `WEB_SCUMM_ALLOW_CUSTOM_PROVIDER=1` opt-in; public HTTPS destinations are still required (loopback, unspecified, private, link-local and local-name hosts are refused in both IP families, including bracketed and IPv4-mapped IPv6 forms). Provider calls never follow redirects, time out after 60 s and read at most 8 MB. The hostname check is static: a public name that resolves to a private address (DNS rebinding) is not detected; run the Studio on a trusted machine.

Supported versions: the current major's last minor gets every fix; each earlier minor gets security fixes for three months after the minor that followed it (at 4.5.0, 23 October 2026: 4.4 until 23 January 2027, 4.3 until 22 January 2027, 4.2.5 until 21 January 2027 on a branch from `v4.2.5`). The table, the same on both pages: [Security policy](https://github.com/Quest-n-Click/quest-n-click/wiki/EN-Contribute-Security-Policy#supported-versions) and [Stability and support](https://github.com/Quest-n-Click/quest-n-click/wiki/EN-Start-Stability#versions). Every asset of the sample game is CC BY 4.0 since 3.7 (`npm run verify:commercial` checks it); licensing questions are documented in `CREDITS.md` and `LICENSE-ASSETS`.
